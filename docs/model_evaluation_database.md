# 공통 모델 평가 데이터베이스

이 데이터베이스는 특정 영상 모델의 프롬프트 문법과 독립적으로 생성 실험과 리뷰를 축적한다.
기존 `runtime/candidate_reviews/entries/*.json` 파일은 수정하거나 삭제하지 않으며, SQLite에는
검색과 비교에 필요한 구조화 데이터와 원본 파일 해시만 저장한다. 영상과 이미지는 BLOB으로
저장하지 않는다.

## 데이터 계층

- `benchmark_cases`: 모델에 독립적인 제작 의도와 기대 결과
- `prompt_variants`: 모델 어댑터가 만든 실제 프롬프트
- `generation_runs`: 모델, 런타임, 설정, 성능과 출력 정보
- `reviews`, `review_issues`: 관찰 사실과 별도의 원인 추정
- `capability_scores`: 공통 평가 축의 0~5점 점수
- `prompt_policies`: 반복 실험으로 검증된 모델별 프롬프트 규칙

기존 리뷰는 `legacy_ltx_2_3_msr_v2` 모델과 `legacy_unknown_runtime` 런타임으로 가져온다.
기록되지 않았던 체크포인트, dtype, 추론 엔진 버전 및 성능 정보는 추측하지 않는다.

## 가져오기

프로젝트 루트에서 실행한다.

```bash
python3 scripts/import_candidate_reviews.py
```

기본 DB 경로는 `runtime/evaluation/evaluation.db`다. 같은 파일은 SHA-256으로 판별해 반복
실행해도 중복되지 않는다. 리뷰 리비전이 증가하면 별도 버전으로 보존한다.

경로를 바꾸려면 다음처럼 실행한다.

```bash
python3 scripts/import_candidate_reviews.py --db /path/to/evaluation.db
```

## 데이터 규칙

- 원본 리뷰 JSON을 가져오기 과정에서 변경하지 않는다.
- 관찰된 현상과 원인 추정을 별도 필드로 유지한다.
- 모델 버전과 체크포인트를 알 수 없으면 `unknown`으로 남기고 추정하지 않는다.
- 새 생성 연동에서는 모델, 체크포인트 해시, 런타임, dtype, 생성 설정과 성능을 기록한다.
- 영상과 이미지 파일은 파일시스템에 두고 DB에는 경로와 SHA-256만 저장한다.
- 리뷰 수정은 기존 행을 덮어쓰지 않고 새 리비전으로 저장한다.

## 모델 테스트 페이지

UI의 `10 모델 테스트`에서 다음 순서로 공통 평가 계획을 만든다.

1. 모델 제작사, 제품군, 버전과 공식 출처를 등록한다.
2. ComfyUI 워크플로우 폴더의 JSON을 모델에 연결한다.
3. 워크플로우를 `official_baseline`, `controlled_variant`, `optimized_variant` 중 하나로 분류한다.
4. 버전 고정된 공통 진단 세트를 선택하고 케이스별 반복 횟수를 정한다.
5. 계획된 세션을 확인한 후 별도 실행 연동 단계에서 생성한다.

워크플로우 등록 시 파일명, 형식과 SHA-256을 저장한다. 파일 내용이 바뀌면 기존 결과와
섞지 않고 다른 프로필로 취급한다. 테스트 세션 생성은 계획만 기록하며 현재 생성 큐나
ComfyUI를 실행하지 않는다.

기본 `video_model_diagnostic_v1` 세트는 12개 케이스로 구성된다.

- 캐릭터 없는 환경
- 단일 캐릭터 정체성
- 두 캐릭터 구분
- 이미지 참조 반영
- 낙상과 지면 접촉
- 손과 소품 상호작용
- 두 인물 간 물건 전달
- 카메라 이동과 행동
- 공간과 장면 연속성
- 한국어 대사와 화자
- 특수 소품 유지
- 15~20초 장기 연속성

## 워크플로우 어댑터와 사전검사

등록된 공식 워크플로우는 원본 파일의 SHA-256이 일치할 때만 검사·컴파일할 수 있다.
파일이 변경되면 기존 프로필을 갱신하지 않고 새 워크플로우 프로필로 등록한다.

어댑터는 다음 공통 값을 실제 ComfyUI API 노드 입력에 연결한다.

- 정규 프롬프트와 선택적 negative prompt
- seed
- 너비와 높이
- FPS와 프레임 수
- 출력 경로

프롬프트 입력 바인딩은 필수이고 나머지는 모델의 공식 워크플로우 능력에 따라 선택한다.
서로 다른 값이 같은 노드 입력에 연결되거나 존재하지 않는 노드·입력을 선택하면 등록을 차단한다.

테스트 세션의 `가상 컴파일 · 사전검사`는 ComfyUI를 실행하지 않는다. 워크플로우 사본에
테스트 값을 적용해 컴파일 해시를 계산하고, 테스트 자산 누락과 워크플로우 변경 여부를
검사한다. 현재 정규 영문 프롬프트는 12개 케이스 모두 준비되어 있으며 `이미지 참조 반영`
케이스는 참조 이미지가 연결될 때까지 차단된다.

## 테스트 자산 라이브러리

공통 테스트 케이스에 필요한 이미지는 `runtime/evaluation/assets`에 내용 해시 기반으로 저장한다.
동일한 이미지가 다시 등록되면 SHA-256이 같은 기존 자산을 재사용하며 DB에는 케이스, 역할과
자산의 연결만 추가한다. 현재 `이미지 참조 반영` 케이스는 `reference_image` 한 장을 요구한다.

지원 형식은 PNG, JPEG, WEBP이며 최대 크기는 50MB다. 확장자만 신뢰하지 않고 파일 시그니처를
검사한다. 자산 미리보기 API는 허용된 평가 자산 폴더와 저장된 SHA-256을 다시 검증한다.
연결 해제는 케이스 연결만 제거하고 해시 자산 원본은 다른 모델과 세션에서 재사용하도록 보존한다.

사전검사에서 자산 요구사항이 있는 케이스는 다음 조건을 모두 만족해야 `ready`가 된다.

- 요구 역할과 최소 개수만큼 자산이 연결됨
- 워크플로우 어댑터에 같은 역할의 이미지 입력이 바인딩됨
- 등록된 워크플로우와 자산 파일의 SHA-256이 유지됨

## 전용 테스트 큐와 실행 기록

사전검사가 `ready`인 세션은 `model_benchmark` 독립 배치로 등록할 수 있다. 일반 제작 배치와
동일한 FIFO worker를 사용하지만 AI 검수와 Retake 자동화는 적용하지 않는다. 실행 직전에
등록 워크플로우와 테스트 자산의 SHA-256을 다시 확인한다.

각 실행은 `generation_runs`와 `test_session_runs`에 먼저 `queued`로 기록된다. 완료 또는 실패 시
생성 시간, GPU·시스템 메모리 최대 사용량, 출력 경로와 해시를 갱신한다. 개별 큐 삭제와 배치
강제 종료도 `cancelled`로 반영한다.

## 공통 결과 검수와 비교

완료된 테스트 실행은 UI의 세션별 `결과 검수`에서 영상, 케이스 의도, 필수 사건과 금지 실패를
함께 확인한다. 리뷰는 다음 정보를 분리해 저장한다.

- 종합 판단, 잘된 부분과 종합 메모
- 문제 유형, 세부 유형, 심각도와 시간 구간
- 의도한 표현, 실제 출력, 차이 설명, 원인 추정과 개선 제안
- 프롬프트 반영, 정체성, 동작·물리, 시간적 일관성, 카메라, 공간 연속성, 오디오, 화질의 0~5점

리뷰를 수정하면 기존 값을 덮어쓰지 않고 새 revision을 만든다. 모델·워크플로우 비교 화면은
각 실행의 최신 human benchmark revision만 사용하며, 평가하지 않은 점수 축은 평균에서 제외한다.
