# H3 연구의 이미지 요청 한도와 세션 운용

관찰된 공급자 오류: 한 요청에 51개 이미지가 포함되어 최대 50개 제한으로 거부됨. 이미지 개수 제한은 영상 해상도·토큰 예산과 별개다. 이번 오류 요청의 실제 본문은 확보하지 않았으므로 직접 첨부와 누적 이력 중 어느 쪽이 51개를 만들었는지는 미확정이다.

## 확인한 코드 문제와 수정

h3_direction_research.py의 기본 sample_fps=4에서 8초 비교는 원본 32장+후보 32장+자산 참조+이전 결과 꼬리 프레임을 보낼 수 있었다. 새 세션이어도 초과한다.

h3_research_media.prepare_media가 요청당 최대 40개 첨부를 지킨다. 초과 시 시간·종류·위치 라벨이 붙은 프레임 시트로 묶고 자산 참조는 개별 이미지로 유지한다. 원본 프레임은 삭제하지 않으며 input.json에 원래 media와 실제 attachments, 각 개수를 기록한다. 시트당 최대 8개 프레임으로도 한도를 지킬 수 없으면 호출 전 시간 구간 분할을 요구한다. 프레임을 몰래 버리지 않는다.

시트는 개수 제한을 다루는 방법이다. 공급자의 이미지 리사이즈로 눈·접촉·문자 등의 세부가 작아질 수 있다. 정밀 검토는 필요한 좁은 구간의 개별 원본 이미지를 40개 이하로 새 요청하여 확인하고, 확인 전에는 통과시키지 않는다. 요청 바이트/픽셀/토큰 한도까지 보장하는 기능은 아니다.

연구 실행기의 opencode run은 --session/--continue/--fork를 사용하지 않는다. 이미지 분석 호출은 각각 독립 세션이고 진행 상태는 experiment.json과 model_calls에 저장한다. 현재 실행 중인 프로세스는 파일 수정 전 코드를 이미 읽었을 수 있으므로 진행 중 작업을 조회한 후 안전한 경계에서 새 프로세스로 재개한다. 동작 중인 생성이나 분석을 중복 실행하지 않는다.

## OpenCode 장기 작업

주 세션은 조정·상태·텍스트 결과만 다룬다. 원본·후보 프레임을 주 세션에서 계속 열지 않는다. 이미지 분석은 위 독립 호출 경로로 실행하고, 결과 JSON·관찰·미확인·파일 경로만 주 세션으로 전달한다. DS 전체 조사도 시간순 묶음 단위로 수행한다. 도구가 이미지 응답을 주 세션에 반환하면 이력 누적 가능성이 다시 생긴다.

현재 세션이 51개 오류로 계속 거부되면 텍스트만 있는 새 조정 세션에서 기존 상태 파일을 읽고 재개한다. 과거 이미지 대화 전체를 복제하거나 같은 요청을 반복 재전송하지 않는다. 새 세션은 이번 복구 방법이지 매번 수동으로 세션을 갈아야 하는 설계가 아니다.

컨텍스트 요약만으로 이미지가 실제 요청에서 제거된다고 가정하지 않는다. 새 세션에서도 한 번에 51개를 첨부하면 같은 오류가 난다. 공급자 한도를 설정으로 올릴 수 있다고 가정하지 않는다.

## 재개 체크

1. generation_pilot_state.json, 현재 새 실험 상태, 실제 큐와 실행 프로세스를 조회한다.
2. 기존 생성·분석 사용량을 이어받는다. 새 세션을 이유로 예산을 초기화하지 않는다.
3. 마지막 완료 분석 뒤부터 독립 이미지 요청으로 재개한다. 작업의 등록 여부가 불확실하면 조회한다.
4. model_calls/*/input.json의 attachment_count가 40 이하인지 확인한다.
5. 수정은 로컬 테스트로 검증했으며 실제 공급자 호출 재검증은 아직 하지 않았다.
